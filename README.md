# 估價單產生器

報價開單工具。單一網頁、完全離線、無後端無套裝依賴，資料直接寫回本機 JSON 檔案。

## 系統需求

**Chrome 或 Edge**。其他瀏覽器仍可使用，但缺少 File System Access API，資料只能存在瀏覽器的 localStorage，無法寫回本機檔案；介面上方會出現提示。

## 快速開始

1. 雙擊 `quotation.html`（或放到本機 HTTP 伺服器下）。
2. 點「📁 建立自動存檔檔案」，選一個 JSON 檔案（預設檔名 `quotation_database.json`）。之後每次修改都會自動寫回該檔。
3. 換電腦、或要改用別份資料時，點「📂 載入其他檔案」。
4. 填好品項後點「🖨️ 列印單據」，會先驗證必填欄位再叫出列印對話框。
5. 要看某客戶一段時間買了什麼，點「📊 購貨統計」（預設今日，可切本月／上月／本季／今年／全部或自訂起訖日；客戶選「全部客戶」則不分客戶彙整）。

## 自動存檔的行為

- 寫入採 debounce（400ms）與單一佇列，快速打字不會造成並發寫壞檔案。
- 若瀏覽器暫存為空而檔案有資料（換機器、清過瀏覽器、`file://` 下被隔離），會沿用**檔案版本**而非覆蓋，狀態列標示「部分資料以檔案版本保留」。這是 v0.2.0 修掉的主要風險：舊版會在這種情況下把歷史單據整個抹掉。
- 連結檔案時先備份原始內容到瀏覽器，可隨時用「↩️ 還原檔案備份」回滾。
- 寫入失敗會把狀態列轉紅並顯示原因，不會假裝成功。

## 客戶專屬價

「⚙️ 商品管理」建立商品基底（預設單位、預設單價）。「👥 客戶管理」建立客戶名單，並為單一客戶覆寫特定商品價格；未設定專屬價的商品自動採用基底價。

買受人欄位**離開焦點**（或按 Enter、點「🔄 重新套用客戶專屬價」）才會重算整張單價。打字中不會覆蓋你手動改過的價格——這是刻意的，舊版每敲一個字就吞掉手動價。

## 客戶購貨統計

「📊 購貨統計」回答「某個客戶在一段時間內買了多少」；客戶選**全部客戶**則不分客戶彙整，用來看整體業績。統計來源是**歷史單據**，所以單據要先按過「💾 儲存單據」才會被算進去；畫面上還沒儲存的那張不算。

- 期間預設為**今日**，另有本月／上月／本季／今年／全部五個快捷，或直接改起訖日（改動後快捷的高亮會消失）。起訖日填反了自動對調。今日快捷把起訖日設成同一天，此時期間只印一個日期。
- 客戶下拉是「**全部客戶** ∪ 客戶名單 ∪ 歷史單據出現過的買受人」，所以手打、沒建進名單的客戶也查得到。「全部客戶」恆為第一個選項，也是沒選過時的預設。它**不佔用 `<option>` 的 value**（value 留空、另掛 `data-all="1"`），判定走 `getReportSelection()` 回傳的描述子——買受人是使用者自由輸入、也會從 JSON 快照原樣讀進來的文字，任何拿它當哨兵值的寫法都可能被一位真實客戶精確撞上，進而把該客戶的單一報表悄悄變成不分客戶。
- 報表分三段：**按月彙整**（單據數、金額）、**品項彙整**（總數量、筆數、金額，依金額排序）、**單據明細**（逐張的日期、單號、金額），最後是期間合計與國字大寫。不分客戶時，單據明細會在日期與單號之間多印一欄**客戶**，尾端的診斷提示也一併附上買受人——否則兩位客戶的單號相同，紙上分不出來是哪張。
- 每行金額走與單據相同的 `roundAmount()`，所以報表、畫面總計、歷史列表、收據四處不會各說各話。數量 ≤ 0、單價為負、或品名有填但數量單價空白的行一律不計入（這種行在單據上本來就是空白金額）。
- 同一張單被存了兩次（連按兩下、或載入舊單後再存一次）不會被算兩遍業績：報表**依「買受人 + 單號」去重，保留最新一筆**，並在尾端註明合併了幾筆。去重鍵一定要帶買受人——單號是各客戶自行編的流水號，不分客戶統計時兩位客戶都可能有「1」號單，只以單號為鍵會把兩張不同的單誤合併掉。
- 單據日期是自由文字，解析採盡力而為：民國年（`115年 11月 4日`）、西元、`/` `.` `-` 分隔、全形數字都認，繁體「號」與省略日標記（`115年11月4`）也認。**解析不出來的單據不會被靜默丟掉**——報表尾端會列出「另有 N 張單據的日期無法判定」並附上單號，這些單據一律不計入期間（含「全部」）。看到這則提示就去修那幾張的日期欄。A4 與熱感兩個版型都會印出這段提示，數字兩版也必然相同。
- 「有沒有資料」要**分開問**：全部客戶看 `getHistoryList()`，單一客戶看客戶名單。兩者母集不同——`saveToHistory()` 不驗證買受人，且 `state.buyer || '未指定買受人'` 中純空白字串（`'   '`）為 truthy 會原樣存入，而名單 `getReportClients()` 會濾掉 trim 後為空的買受人。用名單去判斷全部客戶模式，會把這類已儲存的單據整套無聲吞掉，還反叫使用者去存已經存過的單。
- 空報表那句「期間內查無……」由 `reportEmptyText()` 一處產生，A4 與熱感共用。這是 README 上面那條「兩版必然相同」的其中一個前提，不要在任何一個 builder 裡自行拼這句文案。

## 店家名稱

「⚙️ 商品管理」頂部有一個「店家名稱」欄位，顯示在**熱感單據、統計報表**的店招列，以及 **A4 列印頁首**（來自文件標題）。發行版預設為**空**（見〈發行給客戶〉），填了自己的店名後會記在本機瀏覽器，下次開還在。

- **要完全不顯示店名**：把欄位清空並離開欄位，單據就只印「估 價 單」、報表只印「客戶購貨統計」，A4 頁首也拿掉店名。這是刻意支援的狀態，不是漏填。
- 店家名稱與紙張偏好一樣存在 `localStorage`（`quotation_settings_v1`），**不寫進 JSON 檔案**。理由有兩個：一是它是店面展示而非營業資料；二是檔案那套「空值防抹除」邏輯會把空字串當成遺失、用檔案舊值復活，但清空店名要的就是「真的不顯示」，語意相反——所以它不能進 `PERSISTED_STORES`。
- 代價：換電腦或清過瀏覽器後，店家名稱會回到預設值（不會連同 JSON 檔案一起搬）。要跨機器保留店名，目前得重打一次。
- 輸入會自動去前後空白；店名含 `<` `"` 等字元會安全跳脫，不會破壞收據與報表的排版。

## 顧客簽章欄

同一個彈窗裡有「顧客簽章欄」核取框，**預設關閉**，勾選後熱感單據底部才會多印一行「顧客簽章 ＿＿＿＿＿＿＿＿＿＿」。

- **只影響熱感單據**。A4 列印與統計報表從來沒有簽章欄，這個開關對它們無效——不是壞掉，是本來就沒有。
- 與店家名稱同樣存在 `localStorage`（`quotation_settings_v1`），**不寫進 JSON 檔案**，理由相同（展示偏好不是營業資料）。代價也相同：換電腦或清過瀏覽器後回到預設的「關閉」。
- 三態語意：從未勾過 → 用發行預設 `SHOW_SIGNATURE`；勾過就算取消 → 尊重使用者的「不要」，不會被預設值復活。所以它和店家名稱一樣不能進 `PERSISTED_STORES`，否則「空值防抹除」會把關掉的設定當成遺失蓋回去。
- 存取器在 `paper.js`（`getShowSignature()` / `setShowSignature()`，緊鄰 `PAPER_SETTING_KEY` 那一組），因為它只服務熱感排版；判定的唯一落點是 `buildInvoiceThermalHtml()`，A4 那條路徑不經過它。

## 列印紙張（A4 / 熱感 10cm）

按鈕列的「紙張」下拉有三個選項：A4（直式）、10cm 熱感單據、8cm 熱感單據。預設 A4，選過的結果記在本機（`localStorage`），**不會**寫進 JSON 檔案。

- **A4**：走原本的直接列印，不注入 `@page`，沿用瀏覽器既有邊距——加這個功能不會改變你已經在用的 A4 輸出。
- **熱感**：單據從表格改成直列式收據（店名、標題、單號／日期／買受人、每個品項**一列四欄**「品名｜數量｜× 單價｜金額」、合計、國字大寫；簽章欄**預設不印**，見〈顧客簽章欄〉）。`@page size` 設為 `100mm auto`（`auto` = 連續紙，長度隨內容）配 3mm 左右邊距；8cm 版為 `80mm auto` 配 2mm。**可印內容寬度一律由 `page − 2×左右邊距` 即時算出**（`thermalContentWidth()`），不在 preset 裡手存一份死數字——否則日後調邊距，wrapper 會比實際可印區更寬而裁掉右側，且預覽與實印同時錯、測不出來。
- **品項列是 CSS grid 四軌** `minmax(3em, 1fr) fit-content(6em) fit-content(5.5em) fit-content(6.5em)`（品名｜數量｜× 單價｜金額），三個數值欄各自右對齊、互不牽動——`1500 支` 不會因為隔壁是 `14,475,000` 而被推位。改動前請先讀 `quotation.css` 的註解，每個數字都有理由：
  - **grid 掛在 `.rc-items`（整塊）而不是 `.rc-item`（單列），`.rc-item` 用 `display: contents`**。欄寬是由同一個 grid 內所有儲存格一起決定的；掛在單列上時每列各算各的 max-content，金額較長的列就會把數量推向右，那就是「像表格但欄位錯位」的根源。不用 `subgrid` 是因為它需要 Chrome 117／Safari 16，不支援時整條 `grid-template-columns: subgrid` 被丟掉、子項堆成多行。
  - 用 grid 而非 `flex` + `flex-wrap`：flex 的多列換行以 flex base size（max-content）判線，長品名會獨佔第一列、把數值欄推到下一列，正好和「同一列」的需求相反。
  - **數值欄一律 `fit-content(上限)` 而不是 `auto`**：共用 grid 後欄寬由全壘最寬那筆決定，一筆千萬級金額會把**每一列**的品名欄擠掉三分之一。封頂後異常值改在自己格內折行，其餘各列不受牽連。也必須是 `fit-content()` 而非 `minmax(0, Nem)`——後者的 growth limit 是 Nem，grid 在分配 `1fr` 前會先把空閒空間灌進去，結果等於**固定** Nem，正常單據明明只要 41px 的金額欄也會被佔掉 104px。
  - **上限要寬於任何正常數字**，因為 `fit-content` 已經只取所需，設窄了省不到空間、只會讓正常列無謂折行。前一版設 3em／3.5em／5em 就是踩到這個坑：那是用「最大 128 箱、單價 500」的資料掃瞄出來的，實測一張「1500 支 × 9650 ＝ 14,475,000」的**正常批發單**，數量欄差 4px 裝不下而折行、金額跟著折成兩行。五金批發出現四位數數量、七位數單價是日常，所以拉到收容得了它們為止。
  - 品名軌下限 `3em`：沒有下限時三個數值欄會把品名軌壓到 **0px**，長品名變成一行一字的直排階梯，一張單能吃掉 20 幾公分紙。實測曾出現 25 行／681px。
  - 品名、數量、單價都設 `overflow-wrap: break-word`：中文與帶連字號的型號本來就會換行，但純英數長 token（條碼字號、SKU 序號）沒有任何斷點，缺它會直線畫過去**蓋掉同列的數值欄**，再超出可印寬被裁掉。
  - 單價與金額之間用 `padding-left: 8px` 拉開，不用加大 `column-gap`——gap 會連品名與數量之間一起撐寬，8cm 的 76mm 沒那麼多空間可給。
  - 反直覺但已實測確認：**拆成四欄比合併成三欄更好**。合併格的 max-content（`1500 支 × 9650` ≈ 110px）沒有上限，拆成兩個有上限的獨立欄後是 52 + 48 + 6 gap = 106px，反而省一點。同資料下 10cm 品名欄 138px vs 132px、8cm 70px vs 64px。
  - 已知取捨：金額達 9 位數（億級）以上會在自己格內折成兩行（斷點落在千分位逗號後，折出來是「1,279,999,」／「872」還能唸的樣子）。五金估價單實務上不會出現，且折行優於拖垮同頁其他列的品名欄。
- **字級以 16px 為基底**（考量老花），店名 `1.25em` = 20px 刻意大於標題「估 價 單」的 1em = 16px；**買受人與合計同級** `1.167em` ≈ 18.7px 粗體；備註、國字大寫、提示、簽章欄 `0.917em` ≈ 14.7px。除 `.receipt` 外全部用 `em`，日後要整體放大只改那一個數字。代價是可印寬一行只剩 10cm 約 22 字、8cm 約 18 字（12px 時分別是 29.6／23.9），**8cm 的長品名會折比較多行**——這是已知取捨，不是 bug。
- 因此 `.rc-label` 與文字性 `.rc-value`（買受人、客戶、期間）設為可收縮換行，金額類（`.rc-total`／`.rc-detail`）則恆 `nowrap`。理由是 flex 子項互不讓位時不會報錯，而是**直接溢出被印表機裁掉**，且螢幕預覽看不出端倪；數字被折成兩行又比換行更難讀，所以兩類要反著處理。**例外**：`.rc-buyer .rc-label` 恆不收縮，否則 18.7px 的「買受人」會被壓成「買受／人」折行。這個例外只能寫在 `.rc-buyer` 上、不能寫進 `.rc-label` 本身——報表的 `receiptRow()` 把「買受人＋日期＋單號」這類**動態內容**放進 label 槽，label 一律不收縮會讓報表列溢出。
- 熱感列印的內容先塞進隱藏的 `#printDoc` 容器再 `window.print()`，印完清場（`afterprint` 是保險，避免某些瀏覽器提早回傳而留下打印用的 DOM）。
- 統計報表跟著紙張走：A4 是表格版，熱感是直列版，兩個版型的數字與診斷提示（日期待定、重複單號合併）完全一致。彈窗裡也有一個紙張選擇器，與主畫面的那個**雙向同步**（`syncPaperSelectors()`），換紙張時預覽立刻改版型；預覽**寬度就是實際紙寬**，所見即所印。
- 收據與統計報表的熱感 markup 共用同一組 helper（`receiptRow()` / `receiptItem()`），金額統一走 `formatMoney()`（千分位），不會出現同一個 `.rc-value` 樣式槽在兩份印出上格式不同。
- 一個硬體面的限制：瀏覽器端的 `@page` 只決定版面寬度，無法強迫印表機走紙。若熱感印表機驅動程式裡沒有 100mm（或 80mm）紙張選項，要先在驅動程式建一個自訂尺寸，否則列印對話框會拿預設紙張去套，右側可能被切掉或居中。

## 資料存放

| 位置 | 內容 |
| --- | --- |
| 瀏覽器 localStorage | 主要資料源，鍵名見 `assets/js/core.js` 的 `STORAGE_KEYS` |
| 本機 JSON 檔案 | 上述資料的全量快照，供離線備份與跨機器搬移 |
| IndexedDB | 只記住 JSON 檔案的位置（handle），不含資料 |

例外：列印紙張偏好、店家名稱與顧客簽章欄開關（`quotation_settings_v1`）只存 localStorage，**不進 JSON 檔案**——那份檔案是營業資料的快照，不該被這台機器／這個使用者的列印習慣與店面展示污染（店家名稱與簽章開關不進檔案另有技術理由：會被「空值防抹除」邏輯誤復活，詳見〈店家名稱〉〈顧客簽章欄〉）。

`quotation_database.example.json` 是格式範例，內容全為虛構資料（`範例商品A`／`範例客戶甲`、單號自 `0000001` 起）。實際使用的 `quotation_database.json` 含營業資料，已列入 `.gitignore`，不應進版控。

## 專案結構

```
quotation.html              標記與結構
assets/quotation.css        樣式（含 @media print）
assets/js/branding.js       品牌與發行預設值（APP_NAME、SHOP_NAME、DEFAULT_UNITS、DEFAULT_PRODUCTS、SEQ_BASE、SHOW_SIGNATURE）
assets/js/core.js           常量、純工具、日期與期間解析、使用習慣與店家名稱設定、localStorage、IndexedDB、狀態列
assets/js/currency.js       國字大寫金額
assets/js/store.js          檔案連結、自動存檔管線、防抹除、備份還原
assets/js/invoice.js        單據列、總計、驗證列印、流水號、歷史單據
assets/js/catalog.js        單位與商品管理
assets/js/clients.js        客戶與專屬價管理
assets/js/paper.js          紙張規格（A4 / 熱感）、@page 注入、列印管線、熱感單據排版、簽章欄開關
assets/js/report.js         客戶購貨統計（期間彙整、報表渲染與列印）
assets/js/app.js            datalist 同步、事件委派、啟動流程
```

腳本刻意用 classic script（`<script src>`）而非 ES modules，以維持「雙擊 HTML 直接開啟」在 `file://` 下可用。代價是各檔共享 global scope——新增頂層符號時注意不要跨檔重複宣告，否則整個 app 會載入失敗。

版本號只有單一來源：`assets/js/core.js` 的 `APP_VERSION`，由 `app.js` 填入介面右下角（列印時隱藏）。改版本只動那一處。

## 發行給客戶

本專案沒有 build 步驟、沒有套裝依賴、沒有 `dist/`，所以**發佈物就是一支乾淨的原始碼 zip**，同時也是 AGPL 意義下的 Corresponding Source，不用另外準備。

### 只改一支檔案

要換成另一個發行對象，只改 `assets/js/branding.js`，不要把店名與預設值散著改在 `core.js`：

| 常數 | 發行版預設 | 說明 |
| --- | --- | --- |
| `APP_NAME` | `'估價單產生器'` | 文件標題與 A4 列印頁首的程式名 |
| `SHOP_NAME` | `''` | 預設店家名稱。留空是刻意支援的狀態，單據只印「估 價 單」，由使用者自己在「⚙️ 商品管理」填入 |
| `DEFAULT_UNITS` | `['個','包','盒','箱','公斤','台斤']` | 預設單位清單。**第一個元素**同時是商品查無資料時的兜底單位（`invoice.js` / `catalog.js` 讀 `DEFAULT_UNITS[0]`），清單不可為空 |
| `DEFAULT_PRODUCTS` | `{}` | 預設商品基底。留空讓對方從零建立自己的品項與定價 |
| `SEQ_BASE` | `0` | 流水單號的冷啟動基準，僅在 localStorage 與 JSON 檔案都無紀錄時生效。對方若沿用既有單號體系，只改這裡 |
| `SHOW_SIGNATURE` | `false` | 熱感單據底部是否印顧客簽章欄。預設關閉；對方自己勾選後存 localStorage，不會被這個預設復活 |

`branding.js` 必須是 `quotation.html` 中**第一支**載入的腳本。上述六個常數的唯一宣告點就是它——`core.js` 不得再宣告，否則兩檔串在同一 global scope 會因重複宣告而讓整個 app 載入失敗。

預設值留空的另外一層理由：`isEmptyStore()` 把 `'{}'` 與 `'[]'` 視為空，所以防抹除邏輯會認定「瀏覽器無資料」而沿用檔案版本。若發行版自帶一份假商品當預設，反而會讓首次連結既有檔案時保護錯方向。

### 打包

發佈物只該含**已追蹤**的檔案。`git archive <tag>` 輸出的是該 tag 的 tree，天然不帶未追蹤檔案、不帶 `.git/`、也不帶版控歷史——這才是它優於 `Compress-Archive` 的理由。

⚠️ 別把安全寄託在 `.gitignore` 上。`git archive` **根本不查** `.gitignore`；真正的保證是「該檔從未進過版控」。`.gitignore` 只是防止手滑 `git add -A` 時把真實資料收錄進去的一道副線。

```
git -c core.autocrlf=false -c core.eol=lf archive <tag> --format=zip -o ..\quotation-<tag>.zip
```

`<tag>` 換成要發的那個版本標籤（`git tag -l` 可查）。這裡刻意不寫死版本號：硬編碼的範例在每次升版後都會過時，照著打會把舊版發出去。

`-o` 的路徑請落在 repo **外**（上例的 `..\`）。輸出到 repo 根目錄的話，那個 zip 就成了未追蹤檔案，下一次 `git add -A` 連發行物一起收進歷史。

`-c core.autocrlf=false -c core.eol=lf` 是必要的：`git archive` 會套用與 checkout 相同的 EOL 轉換，在 Windows 預設設定下輸出的是一份 CRLF 副本。功能上沒差別，但這樣發佈物就**不是**你剛驗證過的那份位元組。不加這兩條就先用 `Compare-Object` 或逐檔 `diff` 確認差異僅止於 EOL。

zip 內容應為 `quotation.html`、`assets/`（CSS + 10 支 JS）、`LICENSE`、`README.md`、`quotation_database.example.json`，可選 `.gitignore` / `.gitattributes`。

> ⚠️ **`.git/` 不得交付；本 repo 的歷史未清除前不得公開。** 版控歷史中曾出現真實報價資料，而移除它的 commit 只刪了索引——**舊 blob 仍在歷史裡**。任何人拿到 `.git` 或把它 clone 走公開 repo，都能取出當時的內容。`git archive <tag>` 只輸出該 tag 的 tree，天然不帶歷史。若日後必須把 repo 公開，先用 `git filter-repo` 或 BFG 重整歷史，並一律**視同已外洩**處理。

**不要 minify 或 bundle**：未壓縮的原始碼本身就是對應來源，一旦壓縮過就必須同批再附一份未打包版（§6）。
